## 1. Foundation

### 1.1 Base Template

This vault is built on the Kepano (Steph Ango) Obsidian starter template, which provides a sensible folder structure, base templates, and default settings. To rebuild from scratch, start by downloading the Kepano template from GitHub, then apply the customizations documented below.

### 1.2 Folder Structure

The vault uses the following top-level folders. Folders marked with an asterisk (*) are additions or modifications to the Kepano defaults.

| Folder | Purpose |
|--------|---------|
| Actions | Task lists and to-do items (personal, work, hobby-specific) |
| Categories | Kepano default category index files |
| Creations * | Original content: articles, presentation outlines, research notes, ideas |
| Daily | Daily notes generated by the Daily Notes core plugin |
| Groups * | Meeting group rosters with member photos and wiki links |
| Knowledge * | Reference material and learning notes (e.g., golf tips, language notes) |
| Meetings * | Meeting notes (flat, date-prefixed). Older notes can be moved to `Meetings/History/` after tag review to keep the active folder tidy — `History/` is still a sub-folder of `Meetings/` so the tagger keeps seeing those files. |
| People * | Contact records with metadata, photos, and embedded meeting history |
| Templates | All templates, Bases, and the optional Python/cleanup scripts under `Templates/Scripts/` |
| Topics * | Dynamic pages that aggregate content by tag combinations (Bases lists) |
| Z_archive | Completed to-do actions and other deprecated materials |
| Z_attachments | All image attachments and embedded files (excluded from RAG sync) |

## 2. Core Plugins

The following core plugins are enabled (beyond Kepano defaults):

**Tags View:** Shows all tags in the right sidebar (#). Enable via Settings → Core plugins → Tags view.

**Word Count:** Displays word and character count in the status bar at the bottom of the editor.

**Daily Notes:** Generates daily journal entries. Template: Templates/Journal Template. Folder: Daily.

**Unique Note Creator (zk-prefixer):** Creates timestamped notes. Format: YYYY-MM-DD HHmm. Note: This plugin creates notes in the root folder by default. We use QuickAdd instead for meeting and note creation to control the destination folder.

**Bases:** Enables .base files for database-like views of vault content.

**Sync:** Obsidian Sync for cross-device synchronization.

**Page Preview:** Hover preview of linked notes.

**Bookmarks:** Bookmark frequently accessed notes.

**Outline:** Shows document outline in sidebar.

**Workspaces:** Save and restore workspace layouts.

## 3. Community Plugins

Install all community plugins via Settings → Community plugins → Browse. After installing each plugin, enable it and configure as described below.

### 3.1 QuickAdd

QuickAdd provides every command that creates or acts on notes. Seven are configured; the four that create notes have sidebar icons managed by Commander.

#### New Meeting Command (macro)

- **Step 1:** user script `Templates/QuickAdd/new_meeting.js` — asks for the meeting type (Group, Individual, Ad-hoc) and fills the variables the template uses (see Section 4.1)
- **Step 2:** template `Templates/Meeting Template.md` into **Meetings**, named `{{DATE:YYYY-MM-DD HHmm}}`
- **Hotkey:** Cmd+Shift+M (Ctrl+Shift+M on Windows) · **Sidebar Icon:** lucide-handshake

#### New Note Command

- **Template:** Templates/Note Template.md (asks Authored or Captured)
- **Folder:** Creations · **File Name Format:** `{{DATE:YYYY-MM-DD HHmm}}`
- **Sidebar Icon:** lucide-notebook-pen

#### New Software Note Command

- **Template:** Templates/Software Note Template.md (vendor, product, licence and cost fields)
- **Folder:** Creations · **File Name Format:** `{{DATE:YYYY-MM-DD HHmm}}`

#### New Person Command

- **Template:** Templates/People Template.md
- **Folder:** People
- **File Name Format:** Disabled (prompts for name, use "Lastname, Firstname" format)
- **Sidebar Icon:** lucide-person-standing

#### Insert People Template Command

- **Capture** of `{{TEMPLATE:Templates/People Template.md}}` into the top of the open note — for an **empty** person note, such as one created by clicking a `[[Name]]` link. Into a note that already has properties it adds a second block below them, which Obsidian does not read as properties.
- **Hotkey:** Cmd+Option+P (Ctrl+Alt+P on Windows)

#### Move to Knowledge and Clean Filenames (macros)

- User scripts `Templates/QuickAdd/move_to_knowledge.js` and `Templates/QuickAdd/clean_filenames.js` (see Section 4.6)
- **Move to Knowledge hotkey:** Cmd+Option+K (Ctrl+Alt+K on Windows) · both have sidebar icons

All open in a new tab with focus where they create a note.

> **Important:** For each command, click the lightning bolt icon in QuickAdd settings to enable it as an Obsidian command. This is required before Commander can add it to the sidebar or a hotkey can be assigned.

### 3.2 Templater (retired 2026-10-03)

The template no longer uses Templater, and updates remove it. Templater ran commands written in note text: dynamic commands (`<%+ %>`, and `<%*+ %>` as JavaScript) in **any** note shown in reading view, with no setting or folder limit, and every command in a new note when its creation trigger was on. A clipped web page or a meeting invite could carry one.

What it did is now done by QuickAdd (Section 3.1): plain QuickAdd templates for notes and people, and three small user scripts for the meeting pickers, Move to Knowledge and Clean Filenames. Those scripts run only when their command is run, never because a note was opened or created, and the plugin-integrity check watches them (QuickAdd's macro settings and the script files they name). A command is run from the palette, a hotkey or a sidebar icon — or, as with any QuickAdd choice, from an `obsidian://quickadd?choice=…` link, which Obsidian lets any page or note open; that gives a page nothing it could not already do with Obsidian's own `obsidian://new` link.

Updates remove Templater (they move its folder out of the vault, into the update's backup folder). Templates of your own written for Templater need rewriting in QuickAdd syntax or as a QuickAdd user script. Quit Obsidian before updating: while it is open it keeps every plugin it loaded — Templater included — running until it restarts. The scripts still neutralise `<%` in outside text, and the export gate still refuses a note carrying a dynamic command, for any machine where Templater has been installed by hand.

### 3.3 Dynamic lists with Bases (Dataview retired)

The template used Dataview for live lists until 2026-10-05. Its query language can run JavaScript, so it was retired, and every list moved to Obsidian's core **Bases**, embedded in the note as a `base` code block. An update removes Dataview from existing installs. Used in two ways:

**Dynamic Groups:** a Group file lists the people carrying a tag. Example (DHGC Golfers.md):

````
```base
views:
  - type: list
    name: "Members"
    filters:
      and:
        - 'file.inFolder("People")'
        - 'file.hasTag("DHGC")'
        - 'file.hasTag("Golf")'
    order:
      - file.name
    sort:
      - property: file.name
        direction: ASC
```
````

**Topic Aggregation:** a Topic file lists every note with a tag, or any of several (`or:` in place of `and:`). Example (Golf Instruction.md): the same block without the `file.inFolder` line, filtering on `file.hasTag("Golf")` and `file.hasTag("Instruction")`.

> **Note:** `file.hasTag()` matches a tag in frontmatter or in the note body, and its nested tags too (`file.hasTag("Vendors")` matches `#Vendors/AWS`), as Dataview's `contains(file.tags, …)` did.

## 4. Templates

### 4.1 Meeting Template

**Files:** Templates/Meeting Template.md, filled by the New Meeting macro's script `Templates/QuickAdd/new_meeting.js`

New Meeting first asks for the meeting type:

- **Group:** pick a note from Groups/. Its `[[wiki links]]` become the attendees — minus image embeds (group notes carry photo thumbnails next to each name) and `.base` embeds — and `group` links the chosen group.
- **Individual:** pick a person from People/.
- **Ad-hoc:** type a title (required; Escape cancels the command).

The script puts the results in QuickAdd variables, and the template is plain QuickAdd syntax:

```yaml
---
categories:
  - "[[Meetings]]"
type: {{VALUE:meetingType}}
{{VALUE:titleLine}}{{VALUE:groupSection}}people:
{{VALUE:peopleList}}
classification: confidential
tags: []
---
```

which produces, for a group meeting:

```yaml
---
categories:
  - "[[Meetings]]"
type: Group
group:
  - "[[Group Name]]"
people:
  - "[[Person Name]]"
classification: confidential
tags: []
---
```

Names and the title go into the YAML made inert: line breaks become spaces, quotes and backslashes are escaped, braces are dropped (so nothing becomes a QuickAdd token) and `<%` is split, so a note name or group note cannot break the frontmatter. Calendar meetings normally arrive through the meeting pipeline instead (`meeting_prepopulate.py`), with attendees already filled.

### 4.2 People Template

**File:** Templates/People Template.md

A static template with the following structure:

```yaml
---
categories:
  - "[[Categories/People]]"
Title:
Organization:
Email:
Mobile Phone:
tags: []
---

## Photo


## Notes


## Meetings

![[Meetings.base#Person]]
```

The `## Photo` section is where a photo embed is placed (e.g., `![[Smith-John.png]]`). The `## Meetings` section embeds the Person view from Meetings.base, which dynamically shows all meetings where this person appears in the people property.

### 4.3 Note Template and Software Note Template

**Files:** Templates/Note Template.md, Templates/Software Note Template.md

Both are plain QuickAdd templates — no scripting.

**New Note** asks for the note's type, `{{VALUE:Authored,Captured}}` (Escape cancels the note; the Templater version used to default to Authored): *Authored* is something you wrote yourself (a memo, idea, draft or analysis); *Captured* is material collected from elsewhere (an excerpt or reference). It stamps `created` and `updated` with `{{DATE:YYYY-MM-DDTHH:mm}}`, sets `classification: internal-use-only`, and starts with a `## Notes` section.

**New Software Note** is the same with `type: Software`, plus fields for tracking a product — vendor, product, version, license-type, contract-expiration, annual-cost, owner — and sections for Overview, Environment, Integrations and Notes.

### 4.4 Journal Template

**File:** Templates/Journal Template.md

A simple static template used by the Unique Note Creator (zk-prefixer) for timestamped journal entries. Contains only frontmatter with a created date and default tags:

```yaml
---
created: {{date}}
tags:
  - note
  - journal
---
```

### 4.5 Clipping Template

**File:** Templates/Clipping Template.md

A static template for web clippings saved via the Obsidian Web Clipper browser extension. Provides frontmatter fields for categorization, attribution, and source tracking:

```yaml
---
categories:
  - "[[Clippings]]"
tags:
  - clippings
author: []
url: ""
created: {{date}}
published:
topics: []
---
```

### 4.6 Utility Commands (QuickAdd scripts)

Two commands act on notes rather than create them. Each is a QuickAdd macro running one user script from `Templates/QuickAdd/`, and runs only when its command is run (Section 3.2).

**Move to Knowledge** (`move_to_knowledge.js`, Cmd+Option+K / Ctrl+Alt+K): moves the open note into Knowledge/, and Obsidian updates the links to it. It refuses, rather than overwrites, when Knowledge/ already has a note of that name. Useful for triaging clippings or inbox items.

**Clean Filenames** (`clean_filenames.js`): renames every note in Clippings/ whose name carries characters that trip up links or Windows — bullets, smart quotes, em and en dashes, accented letters, fractions, characters illegal in file names, and a leading dot — and keeps the original name in a `title` property when the clipping has properties. A rename that would collide with an existing note (ignoring case, as macOS and Windows do), a name that would end up empty, and a note whose properties cannot be read are each skipped and counted. See Section 9.5.

## 5. Bases (Database Views)

### 5.1 Meetings.base

**File:** Templates/Bases/Meetings.base

Provides database-like table views of meeting notes. Four views are defined:

- **Meetings:** Default table showing Meeting name, Type, and People columns, sorted by date ascending.
- **Person:** Filtered view showing only meetings where a specific person appears in the people list. Columns: Meeting, Type, Tags, People. Sorted by file name descending. This view is embedded in every People file via `![[Meetings.base#Person]]`.
- **Group:** Filtered view showing only meetings where a specific group appears in the group property. Columns: Meeting, Type, Tags, People. Sorted by file name descending. This view can be embedded in Group files via `![[Meetings.base#Group]]`.
- **Type:** Filtered view showing meetings of a specific type.

**Full Meetings.base configuration:**

```yaml
filters:
  and:
    - categories.contains(link("Meetings"))
    - '!file.name.contains("Template")'
properties:
  note.date:
    displayName: Date
  note.people:
    displayName: People
  note.type:
    displayName: Type
  note.tags:
    displayName: Tags
  note.group:
    displayName: Group
  file.name:
    displayName: Meeting
  note.org:
    displayName: Org
views:
  - type: table
    name: Meetings
    order:
      - file.name
      - type
      - people
    sort:
      - property: date
        direction: ASC
  - type: table
    name: Person
    filters:
      and:
        - list(people).contains(this)
    order:
      - file.name
      - type
      - tags
      - people
    sort:
      - property: file.name
        direction: DESC
      - property: people
        direction: DESC
  - type: table
    name: Group
    filters:
      and:
        - list(group).contains(this)
    order:
      - file.name
      - type
      - tags
      - people
    sort:
      - property: file.name
        direction: DESC
  - type: table
    name: Type
    filters:
      and:
        - list(type).contains(this)
    order:
      - file.name
      - date
      - people
      - org
    sort:
      - property: date
        direction: DESC
```

## 6. Groups and Photos

### 6.1 Group File Format

Group files in the Groups folder contain a list of people with optional 40px photo thumbnails. There are two types of group files:

**Static Groups:** Manually maintained lists with photo embeds and wiki links:

```
![[Smith-John.png|40]] [[Smith, John]]
![[placeholder-person.png|40]] [[Doe, Jane]]
```

**Dynamic Groups:** Bases-powered groups that auto-populate based on tag combinations (see Section 3.3).

### 6.2 Photo Management

Photos are stored in Z_attachments with the naming convention `Lastname-Firstname.png` (or .jpg). Each People file has a `## Photo` section where the photo is embedded.

**Placeholder Image:** `Z_attachments/placeholder-person.png` is a 40x40 transparent PNG used in group files for people who don't have photos yet. This ensures consistent formatting.

**Photo Refresh Process:** A Claude task scans all People files for photos under the `## Photo` section, verifies the photo exists in Z_attachments, then updates all static group files: replacing placeholders with real photos where available, adding placeholders for people without photos, and handling plain wiki links that need photo/placeholder added. To run a refresh, ask Claude to "rerun the photo refresh." A sample Python implementation of the same logic is included below for reference.

**Photo Refresh Script:**

```python
import os, re, glob

people_dir = "People"
attachments_dir = "Z_attachments"
photo_lookup = {}

for f in glob.glob(os.path.join(people_dir, "*.md")):
    name = os.path.splitext(os.path.basename(f))[0]
    with open(f, 'r') as fh:
        content = fh.read()
    photo_match = re.search(r'## Photo\s*\n\s*!\[\[([^\]]+)\]\]', content)
    if photo_match:
        photo_file = photo_match.group(1).split('|')[0].strip()
        if os.path.exists(os.path.join(attachments_dir, photo_file)):
            photo_lookup[name] = photo_file

groups_dir = "Groups"
total_updates = 0
for gf in sorted(glob.glob(os.path.join(groups_dir, "*.md"))):
    with open(gf, 'r') as fh:
        content = fh.read()
    lines = content.split('\n')
    new_lines = []
    file_updates = 0
    for line in lines:
        wiki_match = re.search(r'\[\[([^\]]+)\]\]', line)
        if wiki_match:
            all_links = re.findall(r'\[\[([^\]]+)\]\]', line)
            people_links = [l for l in all_links if not re.match(
                r'.*\.(png|jpg|jpeg|gif|svg|webp|bmp)', l, re.I)]
            if people_links:
                person_name = people_links[0]
                if person_name in photo_lookup:
                    photo = photo_lookup[person_name]
                    expected = f'![[{photo}|40]] [[{person_name}]]'
                else:
                    expected = f'![[placeholder-person.png|40]] [[{person_name}]]'
                if line.strip() != expected:
                    new_lines.append(expected)
                    file_updates += 1
                    continue
        new_lines.append(line)
    if file_updates > 0:
        with open(gf, 'w') as fh:
            fh.write('\n'.join(new_lines))
        total_updates += file_updates
```

**Cropping:** Crop source photo files using Preview on Mac. Obsidian automatically updates the embedded preview when the source file changes.

## 7. Tags Strategy

Tags are the single classification system used across the entire vault. All classification is done through tags rather than maintaining separate topics, categories, or hierarchies. Tags are stored in the frontmatter `tags` property (lowercase "tags") and can also be used inline with `#` notation.

**Conventions:**

- Use consistent capitalization (e.g., "Golf" not "golf").
- Tags can be applied to any file type: People, Meetings, Creations, Knowledge notes.
- When Obsidian's autocomplete suggests the wrong tag while typing, press Escape to dismiss it, then Enter to confirm your typed value.
- Use Tag Wrangler (right-click a tag in the Tags sidebar) to rename or merge tags across the vault.

**Topics as Tag Aggregators:** Files in the Topics folder serve as dynamic views built on tag combinations. Each Topic file contains a Bases list (see Section 3.3) that shows all vault content matching specific tag combinations. This replaces the earlier approach of using a separate "topics" frontmatter property.

## 8. Data Import Procedures

### 8.1 CSV Contact Import

Contacts can be bulk-imported from a CSV file into People records:

- CSV format: Name (Firstname Lastname), Email, Phone, Organization.
- Names are converted from "Firstname Lastname" to "Lastname, Firstname" format for the filename.
- Business names (e.g., "American Express") and entries with only a first name are filtered out.
- Middle initials are detected and handled (e.g., "Yusuf A. Baptiste" becomes "Baptiste, Yusuf").
- Existing People records are checked to avoid duplicates.
- New files are created using the People Template with email, phone, and organization populated.

### 8.2 ICS (Calendar) Attendee Import

Meeting attendees can be extracted from ICS calendar files and added to the People folder:

- Parse the ICS file for ATTENDEE properties.
- Distinguish required vs. optional attendees via the ROLE parameter (REQ-PARTICIPANT vs OPT-PARTICIPANT).
- Convert "Firstname Lastname" to "Lastname, Firstname" format.
- Check for existing People records to avoid duplicates.
- Filter out mailbox/distribution list names (e.g., "Office Of The Dean").
- Create new People files with email populated from the ICS data.

### 8.3 Bulk Organization Updates

Organization fields can be populated in bulk based on email domain patterns. For example, all People with `@hospital.example.org` emails can be set to "Example Hospital" and all `@university.example.edu` emails to "Example University." Ask Claude to match email suffixes to organization names and update the People files accordingly.

## 9. Maintenance Procedures

### 9.1 Photo Refresh

After adding new photos to People files, ask Claude to "rerun the photo refresh" to update all static group files with the latest photos.

**Automating it:** The photo-refresh logic is mechanical (scan People for `## Photo` entries, verify each exists in `Z_attachments/`, update static Group files to replace placeholders with real photos and add placeholders where photos are missing). If you want it to run on a recurring schedule, two options work equally well: (1) register a daily Claude desktop scheduled task with the prompt above, or (2) port the logic to a Python script under `Templates/Scripts/` and load it as a `launchd` agent the same way `com.tag-clippings.plist` is loaded. Either way, no manual intervention is needed once it's set up — adding a person's wiki link to a Group file means the next run inserts the correct photo.

### 9.2 Template Audit

Periodically check that all People files have the full template applied. Some files imported from external sources may only have a heading. Ask Claude to audit the People folder and apply the template to any incomplete files.

### 9.3 Orphaned Attachment Cleanup

Pasted images that are no longer referenced by any note can accumulate in Z_attachments. Ask Claude to check for and delete unlinked "Pasted image" files.

### 9.4 New Topic Creation

To create a new Topic aggregation page, ask Claude to "put all the [TagName] tags in the [TagName] topic file." Claude will create a Topic file with a Bases list in the Topics folder. For multi-tag topics (e.g., Golf + Instruction), specify both tags.

### 9.5 Filename Cleanup

Web clippings often arrive with special characters (•, ★, ?, smart quotes, em dashes) that are incompatible with Windows. The Clean Filenames command cleans every filename in the Clippings folder at once: Cmd+P → "QuickAdd: Clean Filenames", or its sidebar icon. It replaces special characters with safe equivalents, saves the original name as a `title` property in frontmatter, and Obsidian auto-updates all wiki links.

## 10. Obsidian Web Clipper

The Obsidian Web Clipper is an official browser extension for saving web content (articles, research, reference material) directly into your vault as clean markdown files.

### 10.1 Installation

**Chrome / Chromium browsers (Chrome, Brave, Arc, Edge):**

1. Visit the [Chrome Web Store](https://chromewebstore.google.com/detail/obsidian-web-clipper/cnjifjpddelmedmihgijeibhnjfabmlf) and click "Add to Chrome."
2. Pin the extension to your toolbar for easy access.

**Firefox:**

1. Visit the [Firefox Add-ons page](https://addons.mozilla.org/en-US/firefox/addon/web-clipper-obsidian/) and click "Add to Firefox."

**Safari (Mac and iPad):**

1. Search for "Obsidian Web Clipper" in the App Store and install it.
2. Enable it in Safari → Settings → Extensions.

### 10.2 Configuration

1. Click the Web Clipper extension icon in your browser toolbar.
2. Click the gear icon to open settings.
3. Set your vault name to match your Obsidian vault.
4. Configure the default folder for clipped content (e.g., "Clippings" or "Knowledge").
5. Set the default template — the clipper supports variables like `{{title}}`, `{{url}}`, `{{content}}`, `{{date}}`, and more.

### 10.3 Recommended Workflow

1. Browse articles in Chrome (or Safari on iPad) where you're logged into paywalled sites (WSJ, NYT, etc.).
2. Click the Web Clipper icon to save the article as markdown directly into your vault.
3. Obsidian Sync pushes the clipped file to all your devices.
4. Run the Clean Filenames command (Cmd+P → "QuickAdd: Clean Filenames") to sanitize any special characters in filenames for Windows compatibility.
5. Tag the clipped article and move to the appropriate folder (e.g., Knowledge).

### 10.4 Auto-Apply Templates

The Web Clipper supports rules to automatically apply different templates based on the website. This is useful for applying different frontmatter and formatting depending on the source (e.g., news articles vs. technical documentation). Configure these in the extension's settings under "Templates."

### 10.5 Tips

- Clipped content is saved as durable markdown, readable offline.
- Highlights made on the page before clipping are preserved in the markdown.
- The extension works with any site you can view in your browser, including paywalled content you're subscribed to.
- For iPad, Safari extensions work best; Chrome on iPad has limited extension support.

## 11. Troubleshooting and Lessons Learned

**QuickAdd files going to wrong folder:** Check data.json: the "folders" array must contain the target folder name (e.g., `["Meetings"]`). An empty array `[]` causes files to go to the vault root.

**`<%` code showing in a new note:** a template still written for Templater, which the template no longer uses (Section 3.2). Rewrite it in QuickAdd syntax (`{{DATE:...}}`, `{{VALUE:...}}`), or move its logic into a QuickAdd user script.

**A QuickAdd command missing from the hotkey list:** enable it as a command first (the lightning bolt icon in QuickAdd settings).

**Image embeds leaking into meeting people lists:** Group files with photo thumbnails (`![[photo.png|40]]`) caused image references to appear in meeting note people properties. `new_meeting.js` filters out links to image files and `.base` embeds.

**Tags autocomplete replacing typed value:** When typing a new tag in the Properties editor, Obsidian's autocomplete may replace your input. Press Escape to dismiss the suggestion, then Enter or click away to confirm your typed value.

**A Bases list not matching tags:** Use `file.hasTag("Golf")` (no `#`) rather than testing the `tags` property: it catches both frontmatter and inline tags, and nested ones.

**Case sensitivity in tags:** Obsidian treats "Tags" and "tags" as different properties. Standardize on lowercase "tags" to match Obsidian's native Properties editor behavior.

**New note not getting focus after creation:** In QuickAdd settings, ensure "Open File" is enabled and the file opening settings have focus: true.

## 12. Plugin Installation Checklist

When setting up a new vault from scratch, install and configure plugins in this order:

1. Download and open the Kepano starter template.
2. Enable core plugins: Tags View, Word Count, Daily Notes, Bases, Sync (if applicable).
3. Install community plugins: QuickAdd, Tasks, Commander, Omnisearch, Recent Files, Paste Image Rename, Sort and Permute Lines, Tag Wrangler, Update Time on Edit, Metadata Menu.
4. Copy the templates (Meeting, Note, Software Note, People) into Templates/ and the QuickAdd user scripts into Templates/QuickAdd/.
5. Configure QuickAdd as in Section 3.1: the New Meeting, Move to Knowledge and Clean Filenames macros (each runs its user script), the New Note, New Software Note and New Person templates, and the Insert People Template capture. Enable each as a command (lightning bolt icon).
6. Configure Commander: add sidebar icons for each QuickAdd command.
